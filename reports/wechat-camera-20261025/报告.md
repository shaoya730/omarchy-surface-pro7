# Linux 微信摄像头闪退及前摄预览镜像报告

## 希望解决的问题

1. 原生 Linux 微信打开摄像头采集时可能直接退出。
2. 前摄本机预览左右镜像，纸面文字不可正常阅读；希望确认是否可以关闭本机预览镜像，并提供对应开关。

## 测试环境

- 设备：Microsoft Surface Pro 7，Intel Ice Lake。
- 系统：Arch Linux / Omarchy，内核 `7.2.8-4-omarchy-bore-surface`。
- 微信：`wechat-bin 4.1.13.26-1`，运行 `/usr/bin/wechat`，实际程序 `/opt/wechat/wechat`。
- libcamera / IPA / tools / GStreamer 插件：匹配的本地 `0.7.2-4.1`，增加 OV8865 标准自动对焦。
- v4l2loopback：`0.15.4-2`。
- 应用采集端点：`video0` 为前摄，`video1` 为后摄，YUYV 1280×720、30 fps。IPU 内部节点从 `video64` 开始。
- 未使用微信专用摄像头映射、兼容启动器或二进制补丁。

## 闪退记录

- 时间：2026-10-25 15:58:25，Asia/Shanghai。
- 微信进程 PID：6005；故障线程 TID：6549，名称 `CaptureThread`。
- 信号：`SIGABRT`，程序主动中止。
- 操作上下文：机器重启后重新打开原生微信，检查摄像头设置或本机预览；崩溃同时，后摄服务记录到开始采集。
- 当次完整的点击、切换顺序没有录制，重复发生概率尚未量化，不能宣称每次都会复现。

从本机崩溃核心的中止帧提取到以下致命错误，完整核心未附带：

```text
Fatal error in: .../third_party/webrtc/modules/video_capture/linux/video_capture_v4l2.cc, line 416
last system error: 1
Check failed: !race_checker416.RaceDetected()
```

这里的 `last system error: 1` 不能单独解释成设备权限失败；真正触发退出的是线程串行检查。精简堆栈见附件 `崩溃摘录.txt`。

## 与 WebRTC 上游修复的对应关系

上游提交 [c420a240e19e02026f7dfec1261acc4153f1a1ff](https://webrtc.googlesource.com/src/+/c420a240e19e02026f7dfec1261acc4153f1a1ff)，日期 2026-04-21：

> Resolve dcheck due to wrong threading check in VideoCaptureV4L2

该修复使配置阶段的采集互斥锁和串行检查器在线程创建之前离开作用域，避免新线程启动过快，在 `CaptureProcess()` 中再次获取同一检查器时触发断言。

- 上游问题：`webrtc:504490094`。
- 代码审查：[465581](https://webrtc-review.googlesource.com/c/src/+/465581)。
- 已直接读取官方仓库的修复差异，确认它修正生命周期，而非简单删除断言。

已安装微信的只读反汇编与旧顺序吻合：

| 位置（ELF 虚拟地址） | 观察 |
| --- | --- |
| `0x88b2d99` | CaptureProcess 进入串行检查器 |
| `0x88b301b` | 检查失败后进入第 416 行的致命路径 |
| `0x88b26c3` | StartCapture 创建采集线程 |
| `0x88b20fe` → `0x88b1700` | 在后续公共退出路径才释放检查器 |

崩溃条件及指令顺序与上游缺陷高度吻合，仍请腾讯结合实际源码版本确认并移植修复。

## 独立摄像头验证及边界

- 冷启动后两个 RGB 传感器、后摄镜头节点、设备编号及驱动端口设置仍存在。
- 用户摄像头服务曾在登录权限生效前启动失败。该独立问题已修正：加入失败后每 5 秒重试。模拟服务意外退出后，前后摄分别在约 5.20 / 5.19 秒自动恢复。
- 前后摄交替进行四次 180 帧采集，均收到连续更新的帧。一次较短后摄采集仍处曝光预热阶段，未通过图像细节阈值，不能计作完整画质验证。
- 随后实际后摄应用端点完成 900 帧采集，耗时 34.6 秒；亮度稳定，镜头位置最终为 272。
- 以上仅证明系统端点可采集，不能视为微信视频通话已验证。

## 前摄左右镜像

用户使用有文字的纸面对照测试，确认系统独立前摄预览的文字可正常阅读，微信前摄本机预览中的文字左右反向。

这支持“镜像发生在微信本机预览路径”的判断。尚未通过实际通话验证对方收到的画面，不能据此声称发送画面也反向。未找到已确认可用的关闭镜像选项，也未对系统前摄作全局翻转。

请确认本机镜像是否为预期行为，并提供关闭预览镜像的设置，以便展示文字或文档。
